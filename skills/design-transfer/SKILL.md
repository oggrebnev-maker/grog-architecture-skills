# Перенос дизайна один в один

Работу делают скрипты: значения стилей копирует генератор, сверку делает браузер. ИИ пишет только
семантическую разметку и то, что генератор не выражает (резина между ширинами, состояния). Ни один
размер, цвет, шрифт, отступ не печатается руками и не подбирается «на глаз».

Скрипты — в папке этого навыка (её путь Claude Code показывает при загрузке навыка): `S=<папка навыка>/scripts`.
Один раз на машину: `bash <папка навыка>/setup.sh` — ставит Playwright и Chromium в `~/.local/share/design-transfer/` (бесплатно); `install.sh` из `grog-architecture-skills` делает это сам.

## Запреты

1. Не рисовать: не придумывать экраны, состояния, тексты ошибок, цвета, размеры, анимации, маски ввода.
   Нет в пакете — задание дизайнеру в Hand-Off (раздел ниже), без своих вариантов и без временной замены в коде.
2. Делать только то, что нарисовано, плюс то, что владелец прямо разрешил в этом сообщении. Разрешение — буквальное.
3. Пакет макетов — только чтение. Расхождение исправляется в коде.
4. Тексты — дословно из экспорта (`dt.py texts`). Картинки — те же файлы.
5. Переносить страницу целиком: все секции, все ширины, все состояния из пакета. Шапка + одна секция — не перенос.

## Канал с дизайнером (Hand-Off)

Дизайнер (Pencil) работает на компьютере владельца, удалённо. Он сам подключается к серверу по SSH:
кладёт пакеты макетов и ответы в папку Hand-Off проекта (обычно `handoff/`) и читает оттуда сообщения
разработчика. Владелец файлы не переносит. Разработчик работает только с файлами на сервере.

- Pencil к сессии не подключать, MCP Pencil не использовать, `.pen` не открывать — только экспорт из пакета.
- Имена файлов канала не менять (на них настроен дизайнер). Обычно: `CODEX_NEXT_TASK.md` — задание от дизайнера;
  `CODEX_PENCIL_SYNC.md` — сообщения разработчика дизайнеру (дописывать в конец, свои разделы с датой);
  `PENCIL_CODEX_SYNC_REPLY.md` и разделы «Pencil → …» в `CODEX_PENCIL_SYNC.md` — ответы;
  `current-YYYY-MM-DD/` — пакет (HTML-экспорт по ширинам, `renders/*.png`, ресурсы, `README.md`, `SHA256SUMS.txt`).
  Точные имена — в правилах проекта (AGENTS.md / CLAUDE.md).
- **Пришёл пакет**: прочитать ответ дизайнера и README пакета целиком; `sha256sum -c SHA256SUMS.txt` в папке
  пакета; старые пакеты не удалять и не править; новый пакет — дополнение или замена, как написал дизайнер;
  статус DRAFT — переносить можно, объявлять утверждённым нельзя. В `design-transfer.json` → `package`
  указать папку нового пакета, затем `dt.py prepare-ref`.
- **Нужно что-то от дизайнера** (нет экрана, состояния, ширины, текста ошибки): дописать раздел
  `## <кто> → Pencil · <дата> · <тема>` в `CODEX_PENCIL_SYNC.md`: что перенесено, чего нет в пакете (списком,
  по-деловому), что прислать (новый пакет `current-YYYY-MM-DD/` с PNG 1× и HTML-экспортом). Без своих
  вариантов текстов и вида. Дальше — независимая работа; дизайнер увидит файл сам. Владельцу сказать одной строкой,
  что задание записано.

## Порядок

**0. Страж дизайн-системы — до любой работы с пакетом** (правило владельца 19.10.2026):
```bash
python3 $S/guard.py package <папка пакета> --sync <файл сообщений дизайнеру>
```
Сверяет пакет с дизайн-системой без ИИ. Система собирается из всего, что есть: `typography.json` пакета или `guard.tokens`
(роли текста: переменные `type-<роль>-<ширина>` или `tokens.json` дизайн-системы с `type.groups`), `guard.roles` —
роли по ширинам поверх (`{"h1": {"390": [30, 36, 700]}}`), `source/variables.json` пакета и `guard.variables` —
палитра по темам. `guard.py system` печатает собранную систему — сверить, что взято то, что нужно.
- Есть исходник Pencil (`transport/snapshot.html`): текст привязан к роли этой ширины (`$type-h2-1440`), размер /
  межстрочный / толщина совпадают с ролью, шрифт системы, цвета из палитры переменными, компоненты не изменены на месте,
  элементы одного вида выглядят одинаково, нет дробных рамок.
- Исходника нет — по HTML-экспорту (`<страница>-<ширина>[-<тема>].html` в любой подпапке; кадр без ширины в имени —
  ширина верхнего кадра): размер / межстрочный / толщина — роль системы на этой ширине (межстрочный «авто» не сверяется),
  шрифт, цвета (в том числе svg и тени) — из палитры своей темы. Привязку к переменным и компоненты по экспорту не проверить.
- Код 2 (серьёзные: текст вне ролей, цвет вне палитры, компонент изменён, элементы одного вида разные; нет ролей
  текста совсем) — работу не начинать: отчёт дописан дизайнеру (`--sync`, заголовок — `guard.syncHeader` с `{date}` и
  `{package}`, по умолчанию `## Разработчик → Дизайнер · {date} · {package}: …`); владельцу одной строкой.
- Код 1 (нарушения: числа вместо переменных при верных значениях, элемент не из компонента, дробная рамка) — работу
  начать: значения уже верные. Пакет параллельно на доработку (отчёт дописан), после исправленного пакета — доделать.
- Код 0 — чисто.
Исключение — только с «да» владельца: `guard.allow` (`{"code","match","owner"}`, `match` — регулярное выражение по
«кадр | место | деталь»); цвет вне файла системы — `guard.palette`. Свои размеры и цвета в код в обход системы не вносить.
Полный список — `<outDir>/guard-report.json`.

**0а. Прочитать пакет полностью**: README/спецификацию дизайнера, файл общения с дизайнером, все HTML и PNG
кадров состояний. Проверить хеши (`sha256sum -c SHA256SUMS.txt`). Составить список: секции × ширины × состояния;
все ссылки, кнопки и формы страницы — куда ведёт каждая (по реестру ссылок, см. 2а).

**1. Настройка проекта (один раз)** — в корне проекта:
```bash
python3 $S/dt.py init <папка пакета>      # design-transfer.json по файлам <page>-<width>.html
```
Проверить в `design-transfer.json`: `widths` (ширина макета → медиазапрос; по умолчанию граница — середина
между соседними ширинами), `assetUrl` (откуда сайт отдаёт картинки экспорта), `fonts` (локальные файлы
шрифтов — иначе сверка зависит от интернета), `preview` (адрес запущенного сайта), `injectCss` (что снять
на нашей странице для снимка: например, `position: sticky` у шапки; плашки cookie и другие всплывающие окна
плагинов — `display:none`, их нет в макете). Добавить `.design-transfer/` в `.gitignore`.
Второй пакет в том же проекте (другой экран, общие компоненты) — свой файл настроек: `DT_CONFIG=design-transfer.<имя>.json`
перед каждой командой `dt.py`, `guard.py` и `*.mjs`; свои `package`, `mapsDir`, `cssDir`, `refDir`, `outDir`, чтобы не перетирать первый.
```bash
python3 $S/dt.py prepare-ref              # эталон для сверки: ресурсы и шрифты рядом, без интернета
```

**2. На каждую секцию страницы**:
```bash
python3 $S/dt.py sections [page]                         # список секций кадра
python3 $S/dt.py paths "<секция>" [page] [width]          # дерево узлов: тексты «…», [img], [icon]
python3 $S/dt.py scaffold "<секция>" <block> [page]       # <block>.map.json + <block>.skeleton.html
```
- `skeleton.html` → превратить в разметку шаблона: правильные теги (`section`, `h2`, `article`, `a`,
  `button`, `img`, `time`, `ul/li`), доступность, классы сохранить. Повторяющиеся карточки — цикл по данным.
- `map.json` → селектор ← путь узла. Если на какой-то ширине структура другая — путь объектом
  `{"*": "...", "768": "..."}` (сравнить `paths` на разных ширинах). Флаги: `img`, `text`.
- Флаг `box` — текстовая рамка, которую дизайнер задал больше образца (3 строки при 2 строках текста, строка списка):
  px-ширина сохраняется, высота становится `min-height` — длинный реальный текст не обрежется и не наползёт.
- Scaffold находит узел на других ширинах только по тому же имени. Отметка `absent at …` — проверить `paths` на
  этой ширине: узел часто есть под другим именем («Заголовок» вместо «Заголовок раздела») — дописать путь вручную.
- Блок, который на части ширин стоит в другой секции (справка в первом экране на 768 и в истории на остальных):
  одна карта с путями по ширинам, в разметке две копии, лишняя скрыта своим CSS.
- Добавить секцию в `design-transfer.json` → `sections`: `{"key", "url", "map", "css"}`
  (селектор и узел берутся из первой строки карты; при отличии — поля `selector`, `node`; оба могут быть
  по ширинам: `{"*": ".a .x", "768": ".b .x"}`). Шапку и подвал на каждой новой странице тоже сверить:
  отдельные записи с той же картой, `page`, `url` и `node` этой страницы.
- Несколько страниц: `"mapsDir": "scripts/design-import/{page}"` — карты каждой страницы в своей папке.
- **Доска состояний** (один HTML на все ширины: «без истории», «наведение», «недоступно»): отдельная карта с
  `"files": {"*": "<пакет>/event-states.html"}`, пути — от верхнего кадра доски, по ширинам. В `sections` —
  `"check": false` (сверять не с чем). Доска — схема: из неё берутся новые элементы и состояния, сетка страницы
  остаётся из полных макетов; расхождение (поля, кегль) — вопрос дизайнеру.
- Флаг `paint` — правило состояния (`:hover`) из доски: только цвет, фон, цвет рамки, контур; размеры элемента
  не трогаются. Цвет иконки svg (заливка `path`) генератор переносит в `color` (иконки рисуются `currentColor`).
  Раскладку (`display: grid` ряда) `paint` тоже не переносит: состояние ошибки не меняет устройство поля.
  Прозрачный контур рамки доски (`outline … #RRGGBB00`) и `min-width` генератор в `paint` не переносит: иначе
  наведение гасит кольцо фокуса. Правило фокуса в своём CSS — с `!important` (наведение специфичнее фокуса).
- Ссылка внутри текста (Pencil рисует точки векторной полосой) — в коде `text-decoration: underline dotted 1px`
  и `text-underline-offset`; положение черты сверить `img.mjs col` с эталоном.
- Сверка главной, когда первая страница меняется по дате (календарь «сегодня»): `url` секций — с датой макета.
- Страницы, нарисованные на части ширин (админка на 1440/1024): `"pageMedia": {"settings-*": {"1440": "(min-width:1200px)",
  "1024": "(max-width:1199px)"}}` — свои медиазапросы на страницу (ключи — шаблоны имён). `build`, `scaffold`, `check` берут ширины страницы оттуда.
- Путь `"."` в карте — сам кадр страницы (ряд «меню + рабочая область»); фиксированные px кадра (1440×900) снимаются своим CSS.
- Страница, которой нужно состояние до загрузки (вход в предпросмотре, принятая плашка cookie): в секции `"init"` — JS,
  выполняется до скриптов страницы (`addInitScript`); `"wait"` — селектор, который ждать после загрузки (SPA рисует позже).
  `"refCss"` — CSS для эталона: скрыть пометки дизайнера, которых нет на сайте («DRAFT · данные — примеры»).
- **Несколько пакетов**: `"packages": [новые по порядку]` рядом с `"package"`. Файл `<страница>-<ширина>.html`
  берётся из самого нового пакета, где он есть; `prepare-ref` складывает пакеты по порядку (новые поверх старых).
- `"@1024:путь"` в карте — узел другой ширины: элемент показывается и там, где не нарисован (календарь, который на
  телефоне раскрывается по кнопке), со значениями той ширины, где он нарисован. Сказать дизайнеру.
- Картинки экспорта в подпапках пакета (`history-materials/…`): `prepare-ref` копирует все папки, на которые ссылается HTML
  (`url('папка/…')`, `src="папка/…"`). Пустой эталон на месте картинки — проверить, что папка есть в `.design-transfer/ref`.
- Рамки макета меньше своего содержимого (строка 100,5 при 102, экран 580 при 600) — частая ловушка Pencil:
  фиксированная высота обрежет или наложит реальные данные. Флаг `box` + вопрос дизайнеру.
```bash
python3 $S/dt.py build                    # CSS всех карт: один @media на ширину макета. Файл не править.
```
- Кнопка-иконка (☰, ×): в сбросе `button` нужен `padding: 0` — браузер ставит кнопке 1px 6px, и svg 24 px сжимается до 12.
  Иконка с тем же именем в новом пакете может быть нарисована иначе — сравнить контур, не брать первую попавшуюся.
- Свой файл стилей рядом — только то, что генератор не выражает: сброс полей `h2/p`, `display: contents`
  у обёрток, которых нет в макете на части ширин, равная высота карточек ряда (`grid` + `subgrid`),
  `min-width: 0` / `max-width: 100%` против горизонтального скролла, состояния (hover, open, ошибки — только из макета).

**2а. Ссылки, кнопки и формы — живые сразу, при переносе страницы** (чтобы потом не возвращаться к каждой):
- **Реестр ссылок проекта** — один на весь сайт, заводится при переносе первой страницы: ключ → адрес,
  название, состояние («есть» / «резерв»). Формат — как принято в проекте (код + читаемая копия в документах);
  для проверки скриптом — JSON `{"news": {"url": "/novosti", "title": "Новости", "status": "reserved"}}`,
  путь в `design-transfer.json` → `links.registry`. Шаблоны берут адреса только из реестра.
- Каждая ссылка и кнопка макета получает адрес: страница есть — на неё; страницы ещё нет — на закреплённый
  резервный адрес (страница появится по нему, переделывать ссылки не придётся). Якоря — на секции этой
  страницы. Схема адресов сайта — от дизайнера или владельца; нет — одна схема на весь сайт, на языке сайта
  (для русского — слова латиницей: `/novosti`, `/o-hrame/istoriya`), показать владельцу.
- Неактивных (`disabled`) кнопок и ссылок без адреса не оставлять. Исключение — элементы, которые
  включает скрипт на самой странице (`links.allowDisabled`).
- **Формы** работают сразу: всё нарисованное (переключатели, подмена полей, маски, кнопка отправки) —
  действует; `action` — на реестровый резервный адрес приёма. Приёма на сервере нет — отправка заканчивается
  нарисованным состоянием «не отправлено», введённое сохраняется. Подключать настоящий приём, хранение
  персональных данных — только с разрешения владельца.
- **Ошибки форм** — только из единой системы ошибок дизайнера (вид, тексты, порядок проверки, ожидание
  отправки, уведомления) — одна на весь сайт. Нет её в пакете — до переноса формы задание дизайнеру
  на единую систему ошибок форм, своих текстов и вида не делать.
```bash
node $S/links.mjs [/путь ...]    # ссылки без адреса, неактивные кнопки, формы без action, адреса вне реестра
```

**3. Сверка — скриптами, до совпадения**:
```bash
node $S/check.mjs [keys...] [--widths=1440,390]   # размеры блока, % разницы пикселей, недостающие тексты
node $S/overflow.mjs [/путь ...]                  # горизонтальный скролл на любых ширинах 320–2560
```
- Второй предпросмотр (параллельная рабочая копия на своём порту): `DT_PREVIEW=http://127.0.0.1:8091 node $S/check.mjs …` —
  адрес из переменной заменяет `preview` во всех браузерных скриптах.
- Готово, когда по каждой секции и ширине `OK`: размеры совпадают (±`sizePx`), разница ≤ `diffPct`,
  нет недостающих текстов; `overflow.mjs` — без нарушений.
- Блок выше или ниже макета — `node $S/box.mjs <url|файл эталона> <ширина> <селектор...>`: y, высота, padding,
  min-height своего элемента и узла экспорта (`'[data-pencil-name="Имя"]'`), спуститься по детям до разницы.
  Частая причина — рамка Pencil меньше своего текста (54 px при трёх строках по 26): код прав, вопрос дизайнеру.
- Не сходится — смотреть `<outDir>/<key>-<width>-{cur,ref,diff}.png` и `bands` (полосы высоты с разницей):
  `node $S/img.mjs pair a.png b.png y h out.png` — рядом. Остаток в несколько процентов на фотографиях —
  сглаживание; расхождение в тексте, отступах, переносах — ошибка, искать в карте или своём CSS.

**4. Состояния, нарисованные только картинкой (PNG без HTML)** — значения снимать замером, не на глаз:
```bash
node $S/img.mjs row mock.png <y> <x1> <x2>      # цвета вдоль строки: края, рамки, отступы
node $S/img.mjs col mock.png <x> <y1> <y2>      # то же по столбцу: высоты, вертикальные отступы
node $S/img.mjs ink mock.png <x1> <x2> [y1 y2]  # строки текста (верх/низ глифов)
node $S/img.mjs textwidth "600 26px Onest" "Текст" <url страницы со шрифтом>   # кегль по ширине строки
node $S/img.mjs crop mock.png x y w h out.png 2 # увеличить фрагмент
```
Сначала проверить масштаб PNG: ширина известного элемента (поле, подпись) в PNG и в коде должны совпасть.
Собрать состояние в коде, снять снимок, сравнить `ink` и `row/col` эталона и своего — до ±1 px.

**4а. Страж на коде и страницах** — перед сдачей и в каждой выкладке:
```bash
python3 $S/guard.py code           # в шаблонах нет style="" и <style>, в скриптах (и .jsx) нет .style / cssText / style={{…}}
node $S/guard-page.mjs [/путь ...] # каждый видимый текст на 6 ширинах — роль системы; цвета текста, фона, рамок — из палитры
```
- `guard.code` — папки с кодом (по умолчанию те из `frontend/src`, `frontend/app`, `src`, `app`, `resources/views`, что есть).
- `guard-page.mjs` берёт систему у `guard.py system`, ответы сервера — `mock`, страницы — `guard.pages` (иначе адреса секций).
  Темы — `guard.themes`: `[{"name": "dark", "init": "localStorage.setItem('sb-theme','dark')"}]`; цвет сверяется с палитрой
  своей темы. Стенд вместо `preview` — `DT_PREVIEW=<адрес>`.
Подключение стилей — только классами из файлов. Известные старые нарушения — `guard.baseline` (новые не проходят;
исправленное убрать из списка: `--write-baseline` после исправлений). Выкладка проекта запускает обе проверки и
останавливается на новом нарушении.

**5. Сдача**: тесты проекта, `check.mjs`, `overflow.mjs` и `links.mjs` зелёные; выложить, куда велит проект; владельцу —
что перенесено, что не сошлось и почему, что запрошено у дизайнера.

## Как устроен генератор (если результат странный)

- Экспорт Pencil пишет px-ширину родителя узлам «заполнить родителя» → генератор ставит `width: 100%`.
- `flex: 1 1 0` (fill container) → `min-width: 0`; ряды таких детей → `grid` с равными `fr` (Pencil делит
  ряд по внешнему размеру, CSS flex — после отступов).
- px-ширина → плюс `max-width: 100%`, чтобы между ширинами макета ничего не вылезало.
- `prepare-ref` переводит эталон на `border-box` (Pencil считает размеры с отступами и рамкой) и делает
  ту же замену рядов на grid — эталон рендерится как в Pencil.
- Узлы-картинки (`background-image`) с флагом `img` → `object-fit`/`object-position` для `<img>`.
- Узел без имени слоя, но со стилем (подпись внутри кнопки) получает имя по тегу: путь `…/Войти/div`.
- Пакет с локальными шрифтами (`fonts.css` + `fonts/` рядом со страницами): `prepare-ref` копирует их сам, `fonts` в настройках можно не заполнять.
- Состояние нарисовано только на одной ширине: в рабочей копии пакета сделать ссылки `<состояние>-<ширина>.html` на этот файл для остальных ширин (генератору нужен кадр на каждую ширину); правила узких экранов — из README дизайнера, своим CSS. Сверять такие состояния только на нарисованной ширине, всю рамку целиком: в секции `"selector": "<корень>", "node": "<секция>"`.
- Цвета экспорта — значения светлой темы. Тёмную тему не переносить hex-ами: заменить hex на токены дизайн-системы по `source/variables.json` дизайнера (одно значение может быть разными токенами для текста, фона и рамки).

## Установка в другой проект или на другой компьютер

- Навык — в плагине `owner-skills` маркетплейса `grog-architecture-skills` (папка `skills/design-transfer/` репозитория). Сервер: `bash install.sh` из клона репозитория — ставит плагин и Playwright.
- В каждом проекте: `dt.py init <пакет>` → поправить `design-transfer.json` → дальше по «Порядку».
- Экспорт не из Pencil: работает, если у узлов есть атрибут с именем слоя — указать его в `nameAttr`.
