# Перенос дизайна один в один

Работу делают скрипты: значения стилей копирует генератор, сверку делает браузер. ИИ пишет только
семантическую разметку и то, что генератор не выражает (резина между ширинами, состояния). Ни один
размер, цвет, шрифт, отступ не печатается руками и не подбирается «на глаз».

Скрипты — в папке этого навыка (её путь Claude Code показывает при загрузке навыка): `S=<папка навыка>/scripts`.
Один раз на машину: `bash <папка навыка>/setup.sh` — ставит Playwright и Chromium в `~/.local/share/design-transfer/` (бесплатно); `install.sh` из `grog-architecture-skills` делает это сам.

## Запреты

1. Не рисовать: не придумывать экраны, состояния, тексты ошибок, цвета, размеры, анимации, маски ввода.
   Нет в пакете — задание дизайнеру в Hand-Off (раздел ниже), без своих вариантов и без временной замены в коде.
2. Делать только то, что нарисовано, плюс то, что владелец прямо разрешил в этом сообщении. Разрешение — буквальное.
3. Пакет макетов — только чтение. Расхождение исправляется в коде.
4. Тексты — дословно из экспорта (`dt.py texts`). Картинки — те же файлы.
5. Переносить страницу целиком: все секции, все ширины, все состояния из пакета. Шапка + одна секция — не перенос.

## Канал с дизайнером (Hand-Off)

Дизайнер (Pencil) работает на компьютере владельца, удалённо. Он сам подключается к серверу по SSH:
кладёт пакеты макетов и ответы в папку Hand-Off проекта (обычно `handoff/`) и читает оттуда сообщения
разработчика. Владелец файлы не переносит. Разработчик работает только с файлами на сервере.

- Pencil к сессии не подключать, MCP Pencil не использовать, `.pen` не открывать — только экспорт из пакета.
- Имена файлов канала не менять (на них настроен дизайнер). Обычно: `CODEX_NEXT_TASK.md` — задание от дизайнера;
  `CODEX_PENCIL_SYNC.md` — сообщения разработчика дизайнеру (дописывать в конец, свои разделы с датой);
  `PENCIL_CODEX_SYNC_REPLY.md` и разделы «Pencil → …» в `CODEX_PENCIL_SYNC.md` — ответы;
  `current-YYYY-MM-DD/` — пакет (HTML-экспорт по ширинам, `renders/*.png`, ресурсы, `README.md`, `SHA256SUMS.txt`).
  Точные имена — в правилах проекта (AGENTS.md / CLAUDE.md).
- **Пришёл пакет**: прочитать ответ дизайнера и README пакета целиком; `sha256sum -c SHA256SUMS.txt` в папке
  пакета; старые пакеты не удалять и не править; новый пакет — дополнение или замена, как написал дизайнер;
  статус DRAFT — переносить можно, объявлять утверждённым нельзя. В `design-transfer.json` → `package`
  указать папку нового пакета, затем `dt.py prepare-ref`.
- **Нужно что-то от дизайнера** (нет экрана, состояния, ширины, текста ошибки): дописать раздел
  `## <кто> → Pencil · <дата> · <тема>` в `CODEX_PENCIL_SYNC.md`: что перенесено, чего нет в пакете (списком,
  по-деловому), что прислать (новый пакет `current-YYYY-MM-DD/` с PNG 1× и HTML-экспортом). Без своих
  вариантов текстов и вида. Дальше — независимая работа; дизайнер увидит файл сам. Владельцу сказать одной строкой,
  что задание записано.

## Порядок

**0. Прочитать пакет полностью**: README/спецификацию дизайнера, файл общения с дизайнером, все HTML и PNG
кадров состояний. Проверить хеши (`sha256sum -c SHA256SUMS.txt`). Составить список: секции × ширины × состояния;
все ссылки, кнопки и формы страницы — куда ведёт каждая (по реестру ссылок, см. 2а).

**1. Настройка проекта (один раз)** — в корне проекта:
```bash
python3 $S/dt.py init <папка пакета>      # design-transfer.json по файлам <page>-<width>.html
```
Проверить в `design-transfer.json`: `widths` (ширина макета → медиазапрос; по умолчанию граница — середина
между соседними ширинами), `assetUrl` (откуда сайт отдаёт картинки экспорта), `fonts` (локальные файлы
шрифтов — иначе сверка зависит от интернета), `preview` (адрес запущенного сайта), `injectCss` (что снять
на нашей странице для снимка: например, `position: sticky` у шапки). Добавить `.design-transfer/` в `.gitignore`.
```bash
python3 $S/dt.py prepare-ref              # эталон для сверки: ресурсы и шрифты рядом, без интернета
```

**2. На каждую секцию страницы**:
```bash
python3 $S/dt.py sections [page]                         # список секций кадра
python3 $S/dt.py paths "<секция>" [page] [width]          # дерево узлов: тексты «…», [img], [icon]
python3 $S/dt.py scaffold "<секция>" <block> [page]       # <block>.map.json + <block>.skeleton.html
```
- `skeleton.html` → превратить в разметку шаблона: правильные теги (`section`, `h2`, `article`, `a`,
  `button`, `img`, `time`, `ul/li`), доступность, классы сохранить. Повторяющиеся карточки — цикл по данным.
- `map.json` → селектор ← путь узла. Если на какой-то ширине структура другая — путь объектом
  `{"*": "...", "768": "..."}` (сравнить `paths` на разных ширинах). Флаги: `img`, `text`.
- Добавить секцию в `design-transfer.json` → `sections`: `{"key", "url", "map", "css"}`
  (селектор и узел берутся из первой строки карты; при отличии — поля `selector`, `node`).
```bash
python3 $S/dt.py build                    # CSS всех карт: один @media на ширину макета. Файл не править.
```
- Свой файл стилей рядом — только то, что генератор не выражает: сброс полей `h2/p`, `display: contents`
  у обёрток, которых нет в макете на части ширин, равная высота карточек ряда (`grid` + `subgrid`),
  `min-width: 0` / `max-width: 100%` против горизонтального скролла, состояния (hover, open, ошибки — только из макета).

**2а. Ссылки, кнопки и формы — живые сразу, при переносе страницы** (чтобы потом не возвращаться к каждой):
- **Реестр ссылок проекта** — один на весь сайт, заводится при переносе первой страницы: ключ → адрес,
  название, состояние («есть» / «резерв»). Формат — как принято в проекте (код + читаемая копия в документах);
  для проверки скриптом — JSON `{"news": {"url": "/novosti", "title": "Новости", "status": "reserved"}}`,
  путь в `design-transfer.json` → `links.registry`. Шаблоны берут адреса только из реестра.
- Каждая ссылка и кнопка макета получает адрес: страница есть — на неё; страницы ещё нет — на закреплённый
  резервный адрес (страница появится по нему, переделывать ссылки не придётся). Якоря — на секции этой
  страницы. Схема адресов сайта — от дизайнера или владельца; нет — одна схема на весь сайт, на языке сайта
  (для русского — слова латиницей: `/novosti`, `/o-hrame/istoriya`), показать владельцу.
- Неактивных (`disabled`) кнопок и ссылок без адреса не оставлять. Исключение — элементы, которые
  включает скрипт на самой странице (`links.allowDisabled`).
- **Формы** работают сразу: всё нарисованное (переключатели, подмена полей, маски, кнопка отправки) —
  действует; `action` — на реестровый резервный адрес приёма. Приёма на сервере нет — отправка заканчивается
  нарисованным состоянием «не отправлено», введённое сохраняется. Подключать настоящий приём, хранение
  персональных данных — только с разрешения владельца.
- **Ошибки форм** — только из единой системы ошибок дизайнера (вид, тексты, порядок проверки, ожидание
  отправки, уведомления) — одна на весь сайт. Нет её в пакете — до переноса формы задание дизайнеру
  на единую систему ошибок форм, своих текстов и вида не делать.
```bash
node $S/links.mjs [/путь ...]    # ссылки без адреса, неактивные кнопки, формы без action, адреса вне реестра
```

**3. Сверка — скриптами, до совпадения**:
```bash
node $S/check.mjs [keys...] [--widths=1440,390]   # размеры блока, % разницы пикселей, недостающие тексты
node $S/overflow.mjs [/путь ...]                  # горизонтальный скролл на любых ширинах 320–2560
```
- Готово, когда по каждой секции и ширине `OK`: размеры совпадают (±`sizePx`), разница ≤ `diffPct`,
  нет недостающих текстов; `overflow.mjs` — без нарушений.
- Не сходится — смотреть `<outDir>/<key>-<width>-{cur,ref,diff}.png` и `bands` (полосы высоты с разницей):
  `node $S/img.mjs pair a.png b.png y h out.png` — рядом. Остаток в несколько процентов на фотографиях —
  сглаживание; расхождение в тексте, отступах, переносах — ошибка, искать в карте или своём CSS.

**4. Состояния, нарисованные только картинкой (PNG без HTML)** — значения снимать замером, не на глаз:
```bash
node $S/img.mjs row mock.png <y> <x1> <x2>      # цвета вдоль строки: края, рамки, отступы
node $S/img.mjs col mock.png <x> <y1> <y2>      # то же по столбцу: высоты, вертикальные отступы
node $S/img.mjs ink mock.png <x1> <x2> [y1 y2]  # строки текста (верх/низ глифов)
node $S/img.mjs textwidth "600 26px Onest" "Текст" <url страницы со шрифтом>   # кегль по ширине строки
node $S/img.mjs crop mock.png x y w h out.png 2 # увеличить фрагмент
```
Сначала проверить масштаб PNG: ширина известного элемента (поле, подпись) в PNG и в коде должны совпасть.
Собрать состояние в коде, снять снимок, сравнить `ink` и `row/col` эталона и своего — до ±1 px.

**5. Сдача**: тесты проекта, `check.mjs`, `overflow.mjs` и `links.mjs` зелёные; выложить, куда велит проект; владельцу —
что перенесено, что не сошлось и почему, что запрошено у дизайнера.

## Как устроен генератор (если результат странный)

- Экспорт Pencil пишет px-ширину родителя узлам «заполнить родителя» → генератор ставит `width: 100%`.
- `flex: 1 1 0` (fill container) → `min-width: 0`; ряды таких детей → `grid` с равными `fr` (Pencil делит
  ряд по внешнему размеру, CSS flex — после отступов).
- px-ширина → плюс `max-width: 100%`, чтобы между ширинами макета ничего не вылезало.
- `prepare-ref` переводит эталон на `border-box` (Pencil считает размеры с отступами и рамкой) и делает
  ту же замену рядов на grid — эталон рендерится как в Pencil.
- Узлы-картинки (`background-image`) с флагом `img` → `object-fit`/`object-position` для `<img>`.

## Установка в другой проект или на другой компьютер

- Навык — плагин `design-transfer` маркетплейса `grog-architecture-skills`. Сервер: `bash install.sh` из клона репозитория (ставит плагин выключенным и Playwright).
- Проект с интерфейсом: в `.claude/settings.json` проекта — `"design-transfer@grog-architecture-skills": true` в `enabledPlugins` и строка в разделе 3 `CLAUDE.md`.
- В каждом проекте: `dt.py init <пакет>` → поправить `design-transfer.json` → дальше по «Порядку».
- Экспорт не из Pencil: работает, если у узлов есть атрибут с именем слоя — указать его в `nameAttr`.

## Улучшение скилла (правило владельца)

Нашёл ошибку скрипта, ловушку экспорта, ручной замер, который мог бы делать скрипт, или лучший шаг процесса —
сразу, без вопроса, дописать это в сам навык — в клоне `grog-architecture-skills` (`plugins/design-transfer/skills/design-transfer/`),
а не в установленной копии плагина. Проверить, что скрипты работают; версия +1 в `plugins/design-transfer/.claude-plugin/plugin.json`,
строка в `CHANGELOG.md`, push, `claude plugin update design-transfer@grog-architecture-skills`. Сообщить владельцу одной-двумя строками, что добавлено.
