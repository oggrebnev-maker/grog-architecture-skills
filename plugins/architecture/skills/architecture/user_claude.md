# Общие правила владельца

Действуют во всех проектах. Решения владельца в текущем чате важнее этого файла.

## Общение

- Отвечать по-русски. Ответ владельцу — только то, что он спросил, такой длины, какой требует вопрос. Термин — с пояснением простыми словами при первом упоминании; пояснение важнее краткости.
- Писать то, что нужно от владельца: вопрос, решение, действие. Отчёт — только при сдаче работы, коротко: что смотреть, что готово, что нет и почему, что ждёт решения. Промежуточных отчётов, списков решений и отложенного не писать — даже если навык процесса их требует.
- В сообщении — не больше одного вопроса: 2–4 варианта и рекомендация.
- В начале каждого чата включать навык `caveman` и держать до «normal mode».
- Никогда не соглашаться с владельцем без анализа. Вместо этого — сравнить его вариант с лучшим найденным; лучше другой — предложить с причиной.

## Работа

- Необходимую работу делать сразу, без вопроса «делаю?». Спрашивать до работы — только если шаг необратим, удаляет, затрагивает чужую незавершённую работу или требует бизнес-решения владельца (цены, тексты для клиентов, вкус).
- Технические решения, git и ветки (push своей ветки) — самому. Бизнес-правила не выдумывать — спросить.
- Готовое прежде своего: взять готовое → доработать близкое → только если нет совсем — писать своё. Перед новой зависимостью, интеграцией или утверждением о внешнем инструменте — официальная документация через Firecrawl.
- Новая возможность или изменение поведения для пользователя — Superpowers целиком (brainstorming → спецификация → план → TDD). Исправление без изменения поведения — падающий тест → правка → тесты.
- «Готово» — только после тестов и проверки типов проекта без ошибок в этой же сессии. Не прогонял — написать «не проверено».
- Внешние сайты — Firecrawl CLI. Интерфейсы — Claude Design, реализация после «утверждаю» владельца.
- Новые идеи владельца — в `docs/CHANGE_REQUESTS.md` проекта, текущую задачу не бросать.
- Решения, правила и грабли записывать в файлы проекта, не только в память Claude.
- Свои настройки (плагины, разрешения, `~/.claude`, `.claude/settings*.json`) Claude не меняет — защита Claude Code. Дать владельцу строку с `!` в начале (команды — в навыке `architecture`).
- Устройство проекта — навык `architecture` (плагин `grog-architecture-skills`). Узнал важное для всех проектов — правка в репозитории `grog-architecture-skills` по его правилам и сообщение владельцу «Записал в инфраструктуру: …».

## Только после явного «да» владельца

- Публикации, платежи, изменения в живых кабинетах, платные вызовы ИИ.
- Слияние в main, создание репозиториев, deploy.

## Безопасность

- Секреты не в Git, не в документах, не в чате. Значения из `.env*` не читать и не выводить; имена ключей — `bash scripts/env-names.sh <файл>`.
- Коммитить только свои пути. Ограничения среды не обходить.

## Грабли

- Хук `guard-env` блокирует команды со строкой `.env`. Файлы с таким текстом писать редактором; хук не обходить.
- `CLAUDE.md` или `AGENTS.md` бывает символьной ссылкой: запись затирает файл, на который она указывает. Перед записью — `ls -la`.
- После перезагрузки сервера контейнеры без политики перезапуска стоят. Тесты массово падают на подключении к базе — сначала `docker ps -a`.
- Сайт при загрузке ничего не показывает, чтобы тут же убрать или сменить. Тема из браузера — скриптом в `<head>`; экран, зависящий от ответа сервера, до первого ответа пустой (и перед перенаправлением); заставка загрузки видна только после 300 мс; шрифт — `font-display: block`. Проверять покадровой записью первых секунд загрузки (пример — `smarty-business-app`, `frontend/tests/no-flash.spec.mjs`).
