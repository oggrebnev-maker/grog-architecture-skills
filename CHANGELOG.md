# Изменения

## architecture 1.4.0 — 16.10.2026

- Установка обычным сообщением. Запрет «Self-Modification» автоматического режима — «мягкий»: его снимает исключение `autoMode.allow` в личных настройках или сообщение владельца с названными изменениями. `install.sh` (через `lib/user_settings.py`, с тестами) записывает исключение для скриптов этого репозитория — после первой установки достаточно фразы «обнови и примени grog-architecture-skills».
- README, раздел «Установка»: готовая фраза для Claude и команда; порядок для Claude, если защита всё же отказала.

## architecture 1.3.0 — 16.10.2026

- Защита автоматического режима Claude Code не даёт Claude менять свои настройки (плагины, разрешения, `~/.claude`, `.claude/settings*.json`). Установку и настройки теперь запускает владелец одной строкой: `bootstrap.sh` (скачать или обновить репозиторий → `install.sh` → `project.sh` для текущего проекта). Claude даёт строку с `!` в начале.
- Новый `project.sh`: настройки проекта и расширений (маркетплейсы, плагины, запреты чтения), недостающие строки `.gitignore`, `scripts/env-names.sh`. Только добавляет; выключенные владельцем плагины не включает; повторный запуск ничего не меняет.
- README, навык, эталон, общие правила и сообщения `check.py` — о том, что настройки меняет владелец.

## architecture 1.2.1 — 16.10.2026

- `install.sh`: npm-программы — в `~/.local` (без прав администратора), `~/.local/bin` в PATH; команды внутри циклов не читают список (ставились не все навыки).

## architecture 1.2.0 — 16.10.2026

- `manifest.json` — единый список всего, что ставится на сервер, с «зачем» у каждой строки. `install.sh` приводит сервер в соответствие ему: обновляет клон, ставит недостающее, обновляет установленное, называет дубли, ничего не удаляет.
- Новые на всех серверах: `skill-creator`, `pr-review-toolkit`, `typescript-lsp` (+ `typescript-language-server`), `security-guidance`, `playwright`, `hookify` из официального каталога Anthropic; навык `research-first` (niveku/skill-research-first).
- `check.py` проверяет, что все плагины списка включены у пользователя.
- README: порядок «загрузи и примени» для Claude.

## owner-skills — 16.10.2026

- Папка `skills/` в корне — плагин `owner-skills` без номера версии: навык владельца добавляется папкой `skills/<имя>/SKILL.md`, каждый коммит — обновление. `design-transfer` перенесён сюда, отдельный плагин `design-transfer` убран.

## architecture 1.1.0, design-transfer 1.0.0 — 16.10.2026

- Новый плагин `design-transfer` (навык владельца): перенос макетов в код один в один. Ставится выключенным (`defaultEnabled: false`), включается в проектах с интерфейсом через `enabledPlugins`.
- Playwright для его проверок — в `~/.local/share/design-transfer/` (папка плагина заменяется при обновлении); `install.sh` ставит его сам. Версия Playwright — 1.63.0 (выпущена 14 и более дней назад).
- Пути в навыке — «папка навыка» вместо `~/.claude/skills/...`; улучшения навыка — в клоне репозитория с новой версией.
- `architecture`: навык design-transfer вынесен из плагина.

## 1.0.0 — 16.10.2026

Первая версия маркетплейса. Эталон перенесён из проекта «Умный бизнес» и доработан по независимому ревью:
- плагин `architecture`: навык, агенты `reuse-scout` и `manual-keeper`, хук `guard-env`; установка — `install.sh`;
- проект объявляет маркетплейсы и плагины в `.claude/settings.json`, раздел 3 `CLAUDE.md` описывает их, `check.py` сверяет;
- сняты противоречия: необходимое делать сразу, один вопрос в сообщении, порог полного цикла Superpowers, когда сверяться с документацией;
- секреты: `.env.example`, `env-names.sh`, шаблон `.gitignore`, хук блокирует при отсутствии `jq`, ловит `.env.*` и `.envrc`;
- `check.py`: ссылки на файлы, `git check-ignore`, конкретные запреты чтения, порядок разделов, размер в байтах, длина журналов, плагины и таблица инструментов, вложенные расширения, проверки уровня пользователя;
- эталон: ветки, CI, передача сессии через `PROGRESS.md`, версии и обновление.
